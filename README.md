## [cite_start]Introduction about MySQL [cite: 101]

[cite_start]MySQL is a **relational database management system (RDBMS)** based on the **SQL (Structured Query Language)** queries[cite: 102]. [cite_start]It is one of the most popular languages for accessing and managing the records in the table[cite: 103]. [cite_start]MySQL is **open-source and free software** under the GNU license and is supported by **Oracle Company**[cite: 104].

### [cite_start]Most Important Features of MySQL [cite: 105]
* [cite_start]**Relational Database Management System (RDBMS):** This database language is based on SQL queries to access and manage the records of the table[cite: 106, 107].
* **Easy to use:** You only need basic knowledge of SQL. [cite_start]You can build and interact with MySQL by using only a few simple SQL statements[cite: 108, 109, 110].
* **It is secure:** MySQL consists of a solid data security layer that protects sensitive data from intruders. [cite_start]Passwords are also encrypted in MySQL[cite: 111, 112].
* [cite_start]**Client/Server Architecture:** MySQL follows a client/server architecture where a database server (MySQL) and arbitrarily many clients (application programs) communicate with the server to query data, save changes, etc.[cite: 113, 114, 115].
* [cite_start]**Free to download:** It is free to use and can be downloaded from the MySQL official website without any cost[cite: 116, 117].
* **It is scalable:** MySQL supports multi-threading, which makes it easily scalable. It can handle almost any amount of data, up to as much as 50 million rows or more. [cite_start]The default file size limit is about 4 GB, but this can be increased to a theoretical limit of 8 TB of data[cite: 118, 119, 120].
* [cite_start]**Speed:** MySQL is considered one of the very fast database languages, backed by a large number of benchmark tests[cite: 121, 122].
* [cite_start]**High Flexibility:** It supports a large number of embedded applications, which makes it very flexible[cite: 123, 124].
* [cite_start]**Compatible on many operating systems:** MySQL is compatible to run on many operating systems, like Windows, Linux, many varieties of UNIX, OS/2, FreeBSD, and others[cite: 125]. [cite_start]Clients can run on the same computer as the server or on another computer (communication via a local network or the Internet)[cite: 127].
* [cite_start]**Allows roll-back:** MySQL allows transactions to be rolled back, committed, and supports crash recovery[cite: 128, 129].
* [cite_start]**Memory efficiency:** Its efficiency is high because it has a very low memory leakage problem[cite: 130, 131].
* **High Performance:** It is faster, more reliable, and cheaper because of its unique storage engine architecture. [cite_start]It provides very high-performance results compared to other databases without losing essential functionality, and it has fast loading utilities because of the different cache memory[cite: 132, 133, 134, 135].
* [cite_start]**High Productivity:** MySQL uses Triggers, Stored procedures, and views that allow the developer to give higher productivity[cite: 136, 137].
* [cite_start]**Platform Independent:** It can be downloaded, installed, and executed on most of the available operating systems[cite: 138, 139].
* [cite_start]**Partitioning:** This feature improves performance and provides fast management of a large database[cite: 140, 141].
* **GUI Support:** MySQL provides a unified visual database graphical user interface tool named **"MySQL Workbench"** to work with database architects, developers, and Database Administrators. MySQL Workbench provides SQL development, data modeling, data migration, and comprehensive administration tools. [cite_start]MySQL has full GUI support from MySQL Server version 5.6 and higher[cite: 142, 143, 144, 145].
* [cite_start]**Dual Password Support:** MySQL version 8.0 provides support for dual passwords: one is the current password, and another is a secondary password, which allows transitioning to the new password[cite: 146, 147].

## [cite_start]System Development Life Cycle (SDLC) [cite: 148]

[cite_start]The systems development life cycle is a **project management technique** that divides complex projects into smaller, more easily managed segments or phases[cite: 149, 150]. [cite_start]Segmenting projects allows managers to verify the successful completion of project phases before allocating resources to subsequent phases[cite: 151].

[cite_start]Software development projects typically include **initiation, planning, design, development, testing, implementation, and maintenance phases**[cite: 152, 153]. [cite_start]End users of the system should be involved in reviewing the output of each phase to ensure the system is being built to deliver the needed functionality[cite: 157].

---

## [cite_start]PHASES OF SYSTEM DEVELOPMENT LIFE CYCLE [cite: 158]

### [cite_start]INITIATION PHASE [cite: 159]
[cite_start]The Initiation Phase begins when a business sponsor identifies a need or an opportunity[cite: 160, 161]. The purpose is to:
* [cite_start]Identify and validate an opportunity to improve business accomplishments or a deficiency related to a business need[cite: 163, 164].
* [cite_start]Identify significant assumptions and constraints on solutions[cite: 165].
* [cite_start]Recommend the exploration of alternative concepts and methods, including questioning the need for technology[cite: 166, 167, 168].
* Assure executive business and executive technical sponsorship. [cite_start]The Sponsor designates a Project Manager, and the business need is documented in a **Concept Proposal**[cite: 169, 170, 171]. [cite_start]A successful Concept Proposal results in a **Project Management Charter**[cite: 173, 174, 175].
* [cite_start]The phase begins when an opportunity to add, improve, or correct a system is formally requested through a business case[cite: 178, 179]. [cite_start]The business case should, at a minimum, describe the proposal's purpose, identify expected benefits, explain how the system supports business strategies, and identify alternative solutions and as many informational, functional, and network requirements as possible[cite: 180, 181].

### [cite_start]SYSTEM CONCEPT DEVELOPMENT PHASE [cite: 182]
[cite_start]This phase begins after a business need or opportunity is validated by the Agency/Organization Program Leadership and the Agency/Organization CIO[cite: 183, 184]. The purpose is to:
* [cite_start]Determine the feasibility and appropriateness of the alternatives[cite: 186].
* [cite_start]Identify system interfaces[cite: 187].
* [cite_start]Identify basic functional and data requirements[cite: 188].
* [cite_start]Establish system boundaries; identify goals, objectives, critical success factors, and performance measures[cite: 189, 190].
* [cite_start]Evaluate costs and benefits of alternative approaches[cite: 191, 192].
* [cite_start]Assess project risks and identify/initiate risk mitigation actions[cite: 193, 194].
* [cite_start]Develop high-level technical architecture, process models, data models, and a concept of operations[cite: 194, 195].
* [cite_start]This phase explores potential technical solutions, which may include trade-off decisions like using COTS software versus developing custom software[cite: 196, 198, 199, 200].
* [cite_start]Construction of executable prototypes is encouraged[cite: 202]. [cite_start]The **System Boundary Document** is an important reference document[cite: 203].

### [cite_start]PLANNING PHASE [cite: 209]
[cite_start]This is a critical step; careful planning is necessary to coordinate activities and manage project risks effectively[cite: 210, 211, 212]. [cite_start]Project plans refine information from the initiation phase by identifying specific activities and resources required[cite: 214].

* [cite_start]A critical part of the project manager's job is to coordinate discussions to identify and document as many functional, security, and network requirements as possible[cite: 215, 216].
* [cite_start]A plan is developed that documents the approach, including methods, tools, tasks, resources, project schedules, and user input[cite: 217].
* [cite_start]Personnel assignments, costs, project schedule, and target dates are established[cite: 218].
* [cite_start]A **Project Management Plan** is created with components related to acquisition planning, configuration management, quality assurance, concept of operations, system security, verification and validation, and systems engineering management[cite: 219, 220].

### [cite_start]REQUIREMENTS ANALYSIS PHASE [cite: 221]
[cite_start]This phase formally defines the **detailed functional user requirements** using high-level requirements identified earlier[cite: 222, 223]. [cite_start]It also delineates requirements in terms of **data, system performance, security, and maintainability**[cite: 224]. [cite_start]Requirements are defined to a level of detail sufficient for system design to proceed and need to be measurable, testable, and related to the business need[cite: 225, 226].

The purposes of this phase are to:
* [cite_start]Further define and refine the functional and data requirements and document them in the **Requirements Document**[cite: 229, 230].
* [cite_start]Complete business process reengineering of the functions to be supported[cite: 231, 232, 233, 234].
* [cite_start]Develop detailed data and process models (system inputs, outputs, and the process)[cite: 235, 236].
* [cite_start]Develop the test and evaluation requirements that will be used to determine acceptable system performance, which are captured in the **Test and Evaluation Master Plan**[cite: 227, 237, 238].

### [cite_start]DESIGN PHASE [cite: 239]
[cite_start]This phase involves converting the requirements into **unified design specifications** that developers use to script programs[cite: 240, 241].

* [cite_start]Program designs can be constructed using a **top-down approach** (identify and link major components first) or a **bottom-up approach** (identify and link minor components first)[cite: 242, 243].
* [cite_start]Contemporary techniques often use prototyping tools to build mock-up designs[cite: 244]. [cite_start]End users, designers, developers, database managers, and network administrators should review and refine the prototyped designs iteratively[cite: 245, 246].
* [cite_start]The system is designed to satisfy the functional requirements[cite: 248]. [cite_start]Elements considered to mitigate risk include[cite: 249, 250]:
    * [cite_start]Identifying potential risks and defining mitigating design features[cite: 251].
    * [cite_start]Performing a security risk assessment[cite: 252].
    * [cite_start]Developing a conversion plan[cite: 253].
    * [cite_start]Determining the operating environment[cite: 254].
    * [cite_start]Defining major subsystems and their inputs and outputs[cite: 255].
    * [cite_start]Allocating processes to resources[cite: 256].
    * [cite_start]Preparing detailed logic specifications for each software module[cite: 257].
* [cite_start]The result is a draft **System Design Document** which, once approved, becomes the final **System Design Document** (Critical/Detailed Design)[cite: 258, 262, 263].
* [cite_start]The Agency Project Manager concurrently begins development of the **Implementation Plan, Operations and Maintenance Manual, and the Training Plan**[cite: 266, 267, 268].

### [cite_start]DEVELOPMENT PHASE [cite: 269]
[cite_start]This phase involves converting design specifications into **executable programs**[cite: 270]. [cite_start]Effective development standards include requirements that programmers discuss design specifications before programming begins to ensure clear understanding[cite: 271, 272, 273]. [cite_start]Procedural programming (line-by-line scripting of logical instructions) has traditionally been used for large transaction-oriented programs[cite: 274, 275].

The Development phase consists of:
* [cite_start]Translating the detailed requirements and design into system components[cite: 278].
* [cite_start]Testing individual elements (units) for usability[cite: 279].
* [cite_start]Preparing for integration and testing[cite: 280].

### [cite_start]INTEGRATION AND TEST PHASE [cite: 281]
[cite_start]Subsystem integration, system, security, and user acceptance testing is conducted[cite: 282]. [cite_start]The user validates that the functional requirements are satisfied[cite: 283, 284, 285]. [cite_start]OIT Security staff assess system security and issue a security certification and accreditation prior to installation/implementation[cite: 286, 287, 288].

[cite_start]Multiple levels of testing are performed, including[cite: 289]:
* [cite_start]Testing at the development facility by the contractor and possibly end users[cite: 290, 291].
* [cite_start]Testing as a deployed system with end users working with contract personnel[cite: 292, 293].
* [cite_start]Operational testing by the end user alone[cite: 294].
[cite_start]A final Independent Verification & Validation evaluation is performed, and all documentation is reviewed and accepted prior to system acceptance[cite: 295, 296, 297].

### [cite_start]IMPLEMENTATION PHASE [cite: 298]
[cite_start]This phase is initiated after the system has been tested and accepted by the user[cite: 299]. [cite_start]The system is installed to support the intended business functions[cite: 300]. Implementation includes:
* [cite_start]User notification and training[cite: 302].
* [cite_start]Installation of hardware and software onto production computers[cite: 302].
* [cite_start]Integration of the system into daily work processes[cite: 302].
[cite_start]This phase continues until the system is operating in production in accordance with defined user requirements[cite: 303].

### [cite_start]OPERATIONS AND MAINTENANCE PHASE [cite: 304]
[cite_start]System operation is ongoing[cite: 305]. [cite_start]The system is monitored for continued performance, and needed modifications are incorporated[cite: 306]. [cite_start]Operations continue as long as the system can be effectively adapted[cite: 307].

The purpose of this phase is to:
* [cite_start]Operate, maintain, and enhance the system[cite: 310].
* [cite_start]Certify that the system can process sensitive information[cite: 311].
* [cite_start]Conduct periodic assessments to ensure functional requirements continue to be satisfied[cite: 312, 313].
* [cite_start]Determine when the system needs to be modernized, replaced, or retired[cite: 314].
* [cite_start]When modifications are identified, the system may re-enter the planning phase[cite: 308].
